# Руководство администратора — Погодный информер

Документ описывает развёртывание, эксплуатацию и восстановление серверной части приложения.

## 1. Назначение системы

Node.js/Express-сервер:
- отдаёт статический фронтенд (`client/`);
- проксирует запросы к **Open-Meteo** (погода) и **Nominatim** (геокодинг);
- предоставляет интерактивную документацию API: `/api-docs`.

## 2. Минимальные аппаратные и системные требования

| Ресурс | Минимум | Рекомендуется |
|--------|---------|---------------|
| ОС | Windows 10/11, Linux (Ubuntu 22.04+), macOS 12+ | Linux LTS |
| CPU | 1 ядро, 1 ГГц | 2 ядра |
| RAM | 512 МБ | 1 ГБ |
| Диск | 200 МБ свободно | 1 ГБ |
| Сеть | Исходящий HTTPS к `api.open-meteo.com`, `nodata-api.open-meteo.com`, `nominatim.openstreetmap.org` | Стабильный канал |

**Программное обеспечение:** Node.js 18+, npm 9+ (или Docker 24+).

## 3. Установка и запуск

### 3.1. Локально (npm)

```bash
npm install
cp .env.example .env   # Windows: copy .env.example .env
npm start
```

Проверка: http://localhost:5500/ и http://localhost:5500/api-docs

### 3.2. Docker

```bash
docker compose up --build -d
```

Переменные — в файле `.env` (см. `.env.example`).

## 4. Конфигурация (переменные окружения)

| Переменная | Тип | Назначение | Пример |
|------------|-----|------------|--------|
| `PORT` | number | Порт HTTP-сервера Express | `5500` |

Секреты API не требуются: внешние сервисы бесплатные и без ключей.

## 5. Reverse Proxy (Nginx) — опционально для production

Для единой точки входа на портах 80/443 и TLS:

```nginx
server {
    listen 80;
    server_name weather.example.com;

    location / {
        proxy_pass http://127.0.0.1:5500;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

После проверки настройте HTTPS (Let's Encrypt / certbot).

> Для учебного локального запуска Nginx не обязателен.

## 6. Мониторинг и логи

- Логи процесса — stdout/stderr (сообщения старта сервера, ошибки `fetch`).
- Рекомендуется перенаправление в файл или сбор через systemd/journald/Docker logs.
- Проверка health: `GET /api/weather?q=Moscow` → HTTP 200.

## 7. План аварийного восстановления (Disaster Recovery)

### Инцидент: недоступны внешние API погоды/геокодинга

**Симптомы:** HTTP 500, `fetch failed`, пустой прогноз в UI.

**Действия:**
1. Проверить интернет и DNS на сервере.
2. Проверить доступность `https://api.open-meteo.com` и `https://nominatim.openstreetmap.org`.
3. При блокировке провайдера — сетевой обход на уровне инфраструктуры.
4. Перезапустить приложение после восстановления сети.

### Инцидент: критический сбой процесса Node.js

**Симптомы:** порт 5500 не отвечает, процесс завершён.

**Действия:**
1. Проверить занятость порта: `netstat` / `ss -tlnp | grep 5500`.
2. Убедиться в корректности `.env` (валидный `PORT`).
3. Запустить: `npm start` или `docker compose restart`.
4. Просмотреть логи последнего запуска на ошибки модулей.

### Инцидент: конфликт порта

**Симптомы:** `EADDRINUSE` при старте.

**Действия:**
1. Изменить `PORT` в `.env` (например, `5501`).
2. Либо остановить процесс, занимающий порт 5500.

> СУБД в проекте не используется — сценарии восстановления базы данных не применимы.

## 8. Резервное копирование

- Исходный код — репозиторий Git (ветка `psevdo-fork`).
- Конфигурация — файл `.env` (не коммитить в Git).
- Данные пользователя (избранные города) хранятся в `localStorage` браузера, не на сервере.

```bash
git pull
npm install
npm start
```

Для Docker: `docker compose up --build -d`.
